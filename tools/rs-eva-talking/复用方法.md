# 观点变形口播：双系统复用方法 v1.0

记录日期：2026-11-16。适用：16:9、单个前景说话人的观点口播。用户认可的是原样片的画面与节奏；音乐版、新视频和两边界面仍分别验收，不以一次认可代表全部通过。

## 1. 复用的内容

复用深蓝/米白/金色视觉框架、真人连续帧、圆形与圆角方形的平滑变化、人脸跟踪、连续字幕、7种原文版式、单一混音出口。新视频的文字、场景数量、场景边界和成片时长来自新视频，不沿用《35岁危机的本质》的固定时间码和原话。

原样片中的“收入线、账单”等专用图解属于该视频的策划实例。通用版已提供开场、金句、清单、步骤、对照、纸卡、结尾，尚未把所有专用图解扩展成任意主题的自动生成器。不能宣称任意视频都达到原样片同等策划水平。

## 2. 成熟结构与取舍

- EVA 人像窗：复用现有 MIT 组件的 geometry keys + smooth5 插值；修改只涉及动态脸部位置与任务配置，不修改上游共享文件。来源：https://github.com/rovereva/eva-video-style 。保留 LICENSE-EVA.txt。
- 现有切片工坊 Motion 原文编排：沿用 director → 确定性校验 → 模板渲染的结构，模型不能输出可执行 HTML/JS。没有另外购买或安装渲染引擎。
- YuNet：使用机器已有模型与 ONNX Runtime，不为工坊额外安装 OpenCV。解码公式对照 OpenCV 官方实现：https://github.com/opencv/opencv/blob/4.x/modules/objdetect/src/face_detect.cpp 。保留模型 MIT 与 OpenCV 许可文件。

## 3. 三层职责

1. **导演负责原文与结构**：给出原句编号/摘录、语义类型、出现时间。禁止丢失否定、数字和条件，禁止把新文案冒充原话。
2. **模板负责画面约束**：使用固定美术与安全几何，不让模型自由写坐标或代码。人物持续可见，重点按引用时刻出现。
3. **渲染与混音负责可重复执行**：按帧号算时间，等待真人图片解码后截图，保持原声语速；配乐只混一次。

## 4. 统一输入与时钟

共享模块：rs_eva_engine.py。输入包括 video、work、duration、captions、title、brand；work 必须是新目录。字幕格式为 {start,end,text}，时间单位为秒，均相对本次片段。

人生重启接收已有 cues（毫秒），转换为秒。工坊接收既有 transcribe/typo_guard 结果，不重新猜字幕。该样片 52秒附近“第二条绳子”仍有听核标记，不能把推断写成已核实事实。

人生重启将核心版本和manifest指纹纳入现有方案fingerprint，升级后旧预览会要求重做。界面默认BGM、手动关闭及请求参数已通过 ui-bgm-evidence.json 检查；这是函数测试，不冒充实时界面验收。

输出帧数 ceil(实际片段秒数 × 30)，不足一帧的尾差只补到输出帧边界，不截短原声、不循环整条视频。实例写 pack-input.json、director-report.json、face-track-report.json、recipe.json，供复查。

## 5. AI 导演如何接到画面

### 人生重启系统

ms:观点变形口播 → eva_packaging.render_silent → rs_eva_packaging.render_silent → 共享核心。

通过 providers.llm_json(tag=rs_eva.director) 请求一次全片场景选择。模型输出 {scenes:[{ids:[0,1],layout:quote}]}；ids 必须连续、不重不漏覆盖原文，单镜最多4句。layout 仅接受 hook/quote/points/process/contrast/paper/close。

全片规划按字幕内容、模板版本、模型可用状态取缓存。试看仅截取这份全片规划，不另做8秒规划；同一规划供完整导出复用。模板版本更新或字幕改变使缓存失效。调用/校验失败会落为 source-rule-fallback，并在阶段信息和报告里明确标示。

### 切片工坊

去包装 → rs-eva-talking-169 → server.py 提交白名单 → motion_director.prepare → source-bound content_scenes → template_job.py → rs_eva_bridge.py → 共享核心。

使用工坊原有导演、校验及失败兜底。kind、blocks、heading 和原文时间实际驱动版式与文字；人物几何由模板约束。不是把 contentArrangement 标志写成 true 就算接好。

云端生成插画在本模板的提交端与引擎入口均拦截，防止为未使用的图片付费。本模板使用原文版式，保持生成插画关闭。

既有导演 schema 的 canvas 是旧竖屏中间格式，本模板最终 1920×1080/1280×720 画幅由原生模板规格决定。不要为了这个模板扩大旧 schema 的所有画幅权限。

## 6. 人脸、字幕与音频

- 6Hz 采样前景人脸，优先近处主体并考虑位置连续性，7点平滑。检出率不足90%直接提示换净底片或人工核对，不硬输出。
- 只变窗口和图像取景，不拉伸脸。面部中心随窗口变化继续居中。当前这条视频396个独立抽检帧全部落在窗口中心±5%范围；这只证明当前素材。
- 字幕层使用整句原文；屏幕大字直接绑定原文，不写死样片文案。长句/多人/遮挡、剧烈转头需另验。
- 人生重启：智能包装中的“配乐BGM”首次默认开启、可手动关闭，新模板使用本机测试库的舒缓曲、人声闪避和低音量提示音。开关关闭时不混BGM。
- 工坊：渲染端输出原声及模板提示音；BGM由客户端 wrap_audio 收口，尊重原有配乐选择。已有音效通过 sfx_mixed 标志避免重复；不在渲染端再铺一层BGM。
- 本机 BGM 测试库（仅本机测试、勿打包）只作当前机器测试。模板没有打包曲目或字体，local-assets.json 是机器配置，不是可分发授权。音乐缺失要报明，不用“已添加配乐”掩盖。

## 8. 出片验收与停止条件

每条先看短预览，核对人脸、字幕、开头重点和声音，再导整条。整条抽看开头、中间、结尾，逐项查没有吞字、人物越框、字幕压脸、双重配乐、爆音和硬截断。

新增可复用样式要在不同人、不同长短的至少3条净口播上补验。±5%居中、重点与语音的时差、手机可读性等详见上一版双系统验收标准，数值仍是建议标准；不要将用户对一条样片的认可解释成所有阈值已正式批准。

当前未验：真实模型对新视频的策划质量；真实账户下两边UI完整联调；多人/大遮挡/横竖屏互转；工坊重载后的模板可见与提交（待用户授权或操作）。

## 9. 已知踩坑与回归办法

- Windows绝对输出路径必须 path.resolve(ROOT,arg)，不能 path.join 导致盘符重复。已纳入回归。
- Playwright的 TEMP/TMP/TMPDIR 指到任务内 child-temp，避免继承不可写系统临时目录。不要修改系统变量。
- Windows子进程要继承基础环境变量。测试夹具曾只传几个DW变量导致Node随机数初始化失败；补回 os.environ 后客户机自身Node已跑通，没有更换系统组件。
- 独立验脸先按输出原始帧号取样，不能用fps滤镜重新采样后仍将输出编号当原始时刻。前者会在快速移动窗口时产生假失配。先后失败记录保留；最终改为全帧解码，每5帧核一次，396/396通过。
- 工坊既有影院模板有目录项但缺登记校验，导致整个catalog读取失败。本轮按既有身份锁补齐，不改它的画面。新增模板也校验ID/目录/画幅/容量。
- 字体资产仍沿用已有核验记录；已认可画面继续用原字体，不把未经复核的字体加入新模板。

## 10. 回滚与维护

重跑契约检查：使用工坊 tools/deepwrap/.venv/Scripts/python.exe -X utf8 执行本目录 test_rs_eva_contract.py。需要重新出视频的脚本会拒绝旧任务目录；保留旧成果并使用新目录，不能靠删旧目录掩盖失败。
